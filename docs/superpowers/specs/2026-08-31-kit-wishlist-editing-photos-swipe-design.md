# Kitrack 購入候補編集・写真・スワイプ表示改善設計

## 目的

Kitrackの買い物リストに登録した購入候補を後から編集できるようにし、所有キットと同様に最大10枚の写真を保存できるようにする。購入候補をBoxへ移動した場合は、写真も所有キットへ引き継ぐ。

併せて、Kitrackの一覧をスワイプした際に背面のアクション表示が行へ透けて重なって見える問題を、Colorackと同じ描画方式へ揃えて解消する。

本設計は `2026-08-31-kit-wishlist-ownership-separation-design.md` の「購入候補は所有キットと完全に独立する」という方針を維持したまま、当時スコープ外だった購入候補の編集と写真を追加する。

## 採用方針

### 購入候補の編集

- 買い物リストの行をタップすると、既存のキット追加モーダルを購入候補編集モードで開く。
- 編集対象は名前、メーカー、シリーズ、種別、スケール、価格、メモ、写真とする。
- Box、制作ステータス、使用色は購入後の情報なので表示しない。
- タイトルは新規時の「キットを追加」と区別し、編集時は「購入候補を編集」とする。
- 名前とメーカーの必須条件、価格の整数検証、未保存変更の破棄確認は既存フォームと同じ挙動を維持する。
- 一覧には先頭写真をサムネイル表示し、写真がない場合は既存キット一覧と同じプレースホルダーを表示する。

所有キット専用の `KitDetailModal` はBox、制作ステータス、使用色を前提としているため購入候補には流用しない。入力項目と写真UIを既に持つ `AddKitModal` を新規・編集の両方へ拡張する。

### 写真データ

既存の `kit_photos` は `kit_id NOT NULL` の所有キット専用テーブルとして維持し、購入候補専用の子テーブルを追加する。

```sql
CREATE TABLE IF NOT EXISTS kit_wishlist_photos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  wishlist_id INTEGER NOT NULL,
  uri TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  added_at TEXT DEFAULT (datetime('now')),
  synced_at TEXT,
  storage_path TEXT
);
```

既存 `kit_photos` を多態化するとSQLiteのテーブル再構築と全既存写真の移行が必要になるため採用しない。購入候補行へ写真URIのJSONを保存する方式も、参照整合性、並び替え、Box移動、クラウド復元が不安定になるため採用しない。

写真ファイルは既存の `lib/kitPhoto.ts` と `KitPhotoGrid` を再利用し、端末の `documentDirectory/kit-photos/` 配下へ圧縮保存する。上限は所有キットと同じ10枚とし、追加、拡大表示、削除、左右の並び替えを提供する。

### 編集時の写真ドラフト

- モーダルを開いた時点の写真と、編集中に追加した写真を区別して保持する。
- キャンセル時は編集中に新しく作成した写真ファイルだけを削除し、既存写真は変更しない。
- 保存時は購入候補の項目更新と写真行の同期を同一排他トランザクションで行う。
- 既存写真の `synced_at` と `storage_path` はURIが同じ限り維持し、並び替えだけで再アップロードしない。
- 保存成功後、編集で外された既存写真のローカルファイルを削除する。DB更新が失敗した場合は既存写真を削除しない。

## Boxへの移動とUndo

購入候補からBoxへの移動は、次を同一排他トランザクションで行う。

1. 選択したBoxに `status = 'not_started'` の所有キットを作成する。
2. `kit_wishlist_photos` の写真行を、新しい所有キットの `kit_photos` へコピーする。
3. `uri`、`sort_order`、`synced_at`、`storage_path` を維持する。
4. 購入候補写真行と購入候補本体を削除する。

物理写真ファイルは同じURIを継続利用するため、コピーも削除もしない。

移動直後のUndoでは逆方向に写真行を戻して購入候補を復元し、作成した所有キットを削除する。現状のUndo処理にある所有キット写真ファイルの削除は行わない。これにより移動・Undoのどちらでも写真を失わない。

## 購入候補の削除とUndo

- 購入候補削除時は本体と写真行を同一トランザクションで取り除き、Undo用に両方のスナップショットを返す。
- Undo可能時間中は写真ファイルを残す。
- Undoした場合は購入候補と写真行をまとめて復元する。
- Undoされずトーストが閉じた場合に、参照されなくなったローカル写真を削除する。
- アプリ終了などで期限後削除が実行されなかった場合に備え、DB初期化時に `kit_photos` と `kit_wishlist_photos` のどちらからも参照されない `kit-photos` 配下のファイルを掃除する。

DBトランザクション確定前に写真ファイルを削除しない。ファイル削除の失敗はDBを巻き戻さずログへ残し、次回の孤立写真掃除で再試行する。

## クラウドバックアップ

Standardプランで所有キット写真がバックアップされる既存仕様に合わせ、購入候補写真も同じ条件で対象にする。

- バックアップスキーマをv6へ更新する。
- v6の購入候補には端末内IDから作る `localRef` を持たせる。
- 所有キット写真とは別に `kitWishlistPhotos` 配列を追加し、`wishlistLocalRef`、`storagePath`、`sort_order` を保存する。
- 未同期写真のアップロード処理は `kit_photos` と `kit_wishlist_photos` の両方を対象にする。
- 復元時は写真を全件ダウンロードできたことを確認してから、購入候補と候補写真を同一DBトランザクションで再作成する。
- v1〜v5バックアップには候補写真がないため、購入候補本体だけを従来どおり復元する。
- 写真バックアップ権限がない場合は候補写真参照を送信・復元しない。
- アカウント切り替えや写真バックアップ権限変更時の同期情報リセットは両写真テーブルへ適用する。

既存Storageの `users/{uid}/kit-photos/` 配下を共用するため、Storageルールやアカウント削除時のパスは変更しない。

## スワイプ表示

調査の結果、`Swipeable` のアクションは行の背面に配置されるが、Kitrackの行背景が透過しているため、ドラッグ中にアクション色と文字が行へ透けて重なって見えている。Colorackでは `PaintRow` が `colors.surface` を描画しており、この問題が起きない。

以下のKitrack共通行へ `backgroundColor: colors.surface` を追加する。

- 所有キット／完成キットで共用する `app/(tabs)/kits.tsx` の行
- 買い物リストの `app/(tabs)/kit-wishlist.tsx` の行

新しいジェスチャー依存や重なり順の調整は追加しない。スワイプ方向、アクション幅、色、操作確定タイミングは維持する。

買い物リスト行はタップで編集、左右スワイプでBox移動／削除とする。所有・完成キット一覧にも既存のスワイプ操作と同等のアクセシビリティアクションを付け、スクリーンリーダー利用時にジェスチャーだけへ依存しないようにする。

## リセットとデータ移行

- 既存ユーザーは起動時に空の `kit_wishlist_photos` テーブルが追加され、既存購入候補は変更しない。
- 旧 `kit_lists` 由来の購入候補へ写真を推測して紐付けない。
- 「キット買い物リストを初期化」は候補写真行と購入候補本体を削除し、参照されなくなった写真ファイルも削除する。
- 「キット保管箱を初期化」は所有キット写真だけを対象とし、購入候補写真を削除しない。

## エラー処理

- 保存失敗時はモーダルを閉じず、既存データと既存写真を保持する。
- 写真の追加・削除・並び替え中は保存の連打を防ぐ。
- Box移動、削除、Undo、バックアップ復元は本体と写真を一つの整合単位として扱う。
- 写真ダウンロードが一部失敗した復元ではDBを入れ替えず、途中で作成したファイルを掃除する。
- 一覧行の編集中・移動中・削除中は同じ行への重複操作を無視する。

## 検証

- 新規購入候補へ1〜10枚の写真を保存し、再表示後も順序が維持される。
- 買い物リスト一覧に先頭写真が表示される。
- 行タップで既存値と写真が読み込まれ、各項目と写真を編集できる。
- 編集を破棄すると既存データが変わらず、編集中に追加した写真ファイルだけが削除される。
- 保存失敗時に既存写真を失わない。
- Box移動で全写真と順序、同期情報が所有キットへ引き継がれる。
- Box移動のUndoで全写真が購入候補へ戻る。
- 候補削除のUndoで全写真が戻り、Undoしなかった場合は孤立写真が削除される。
- 買い物リスト初期化が候補写真を削除し、所有キット写真を削除しない。
- 所有キット／完成キット／買い物リストの全行で、スワイプ中に背面アクションが透けない。
- 行タップとスワイプが競合せず、アクセシビリティアクションから同じ操作を実行できる。
- v6バックアップの往復で購入候補写真が復元される。
- v1〜v5バックアップを復元してもエラーにならず、候補写真は空になる。
- `npm run test`、`npm run typecheck`、`git diff --check` が通る。
- iOS／Android向けExpo exportが完了する。

## スコープ外

- 購入候補のBox、制作ステータス、使用色。
- 購入候補と所有キットの永続的な関連付け。
- 一つの購入候補から複数の所有キットを作る機能。
- 写真へのキャプション、タグ、画像編集。
- 新しい写真ライブラリやスワイプライブラリの導入。
