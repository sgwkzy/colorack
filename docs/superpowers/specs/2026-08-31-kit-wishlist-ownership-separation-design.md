# Kitrack 買い物リスト・所有キット分離設計

## 目的

Kitrackの買い物リストを「購入候補」、Box内のキットを「所有キット」として完全に分離する。購入前の候補にBoxや制作ステータスを持たせず、購入時だけ移動先Boxを決めて所有キットへ変換する。

併せて、キット使用色の編集アクションを内容に合う文言へ修正する。

## 現状の問題

現在の `kit_lists` は独立した購入候補ではなく、`kits` の行に付ける印である。そのため、買い物リストへ登録した時点でデフォルトBoxの未着手キットが作られ、以下の不整合が起きている。

- 買い物リストに未着手・制作中などの所有後ステータスが表示される。
- 所有キット詳細から買い物リストへ追加できる。
- キット削除、Box削除、キット保管箱の初期化が買い物リストにも連動する。
- 買い物リストからBoxへ移す操作が存在しない。
- `kit_lists` がクラウドバックアップに含まれず、復元時には孤立した紐付けが残り得る。

## 採用するモデル

### 購入候補

独立した `kit_wishlist` テーブルに保存する。

- `id`
- `name`
- `maker`
- `series`
- `category`
- `scale`
- `price`
- `note`
- `added_at`

`kit_id`、`box_id`、制作ステータス、写真、使用色は持たせない。購入候補と所有キットの間に永続的な参照関係も持たせない。

### 所有キット

既存の `kits` を継続利用する。購入候補をBoxへ移した時点で新しい `kits` 行を作成し、その購入候補は削除する。

同じ購入候補から複数の所有キットを作る機能、購入候補の数量管理、移動後も候補を残す機能は実装しない。

## 買い物リスト画面

所有キット一覧の `KitsScreen` 流用をやめ、`kit_wishlist` 専用画面にする。

- 行にはキット名、メーカー、シリーズ、スケール、価格を必要な範囲で表示する。
- Box、未着手・制作中・完成ステータス、写真、使用色は表示しない。
- 左スワイプの「購入済み」でBoxへ移す。
- 右スワイプの「削除」で購入候補だけを削除する。
- フィルターは名前、メーカー、シリーズ、種別、スケールに限定する。
- ソートは追加順、名前順、メーカー順を維持する。
- 追加フォームは既存のキット入力項目を再利用するが、写真とBoxは表示しない。

購入候補の詳細・編集画面は今回追加しない。現在の所有キット詳細を開く挙動は削除する。

## Boxへ移す操作

1. キットBoxが1件なら、そのBoxを移動先として直ちに処理する。
2. キットBoxが複数なら既存の選択UIで移動先を選ばせる。
3. 選択をキャンセルした場合は何も変更しない。
4. 選択したBoxへ `status = 'not_started'` の所有キットを作成する。
5. 作成成功後、元の購入候補を削除する。

所有キット作成と購入候補削除は同一DBトランザクションで行う。途中で失敗した場合はどちらも変更しない。

成功後は既存のトーストパターンで「元に戻す」を提供する。Undoは作成した所有キットを削除し、元の購入候補を復元する。Boxが0件になることは初期化処理で防いでいるが、実行時に0件ならエラー表示して候補を残す。

## 所有キット側の変更

- `KitDetailModal` の買い物リスト追加・解除ボタンと関連状態を削除する。
- キット削除とBox削除から買い物リスト削除処理を外す。
- 「キット保管箱を初期化」は所有キットとキットBoxだけを初期化し、買い物リストを残す。
- 「キット買い物リストを初期化」は購入候補だけを削除する。

## 既存データ移行

旧 `kit_lists` と `kits` を結合し、該当するキット情報を `kit_wishlist` へコピーする。旧実装では、買い物リストから追加したキットと、所有キット詳細から買い物リストへ追加したキットを判別できない。

データ消失を避けるため、移行元の `kits` 行は削除・変更しない。コピーと旧 `kit_lists` の削除を単一トランザクションで行い、再実行による重複を防ぐ。移行後に既存の所有キットと購入候補が同時に見える場合があるが、推測による所有データ削除は行わない。

## クラウドバックアップ

バックアップスキーマをv5へ更新し、購入候補配列を追加する。

- バックアップ作成時に `kit_wishlist` を含める。
- `isLocalDbEmpty()` で購入候補もユーザーデータとして数える。
- 復元時は端末側の購入候補を明示的に削除してから再作成する。
- v1〜v4バックアップには購入候補情報がないため、推測して復元しない。
- 旧 `kit_lists` の孤立行を復元後に残さない。

## 使用色の文言

キット詳細から開く使用色編集モーダルのタイトルを「配合を編集」から「色情報を編集」へ変更する。混色シミュレーターの保存済み混色は配合自体を編集するため、既存の「配合を編集」を維持する。

## エラー処理

- Box選択のキャンセルはエラー扱いにしない。
- Box取得、移動、削除、復元に失敗した場合は候補を残し、既存のエラー表示を使う。
- 連打による二重移動を防ぐため、処理中の行操作を無効化する。
- Undo対象は直前に作成した所有キットIDで特定し、同名キットを誤って削除しない。

## 検証

- 新規購入候補にBox・制作ステータスが付かない。
- Boxが1件なら選択なしで移動し、候補が消えて未着手の所有キットが作られる。
- Boxが複数なら選択したBoxだけに移動する。
- Box選択キャンセルとDB失敗時に候補が残る。
- Undoで所有キットが消え、購入候補が復元される。
- 所有キット、Box、キット保管箱の初期化が購入候補を削除しない。
- 買い物リスト初期化が所有キットを削除しない。
- 旧 `kit_lists` からの移行を再実行しても重複しない。
- v5バックアップの往復で購入候補が保持される。
- v1〜v4復元後に旧紐付けや別アカウントの購入候補が残らない。
- キット使用色だけが「色情報を編集」と表示され、保存済み混色は「配合を編集」のままである。
- `npm run test` と `npm run typecheck` が通る。

## スコープ外

- 購入候補の数量管理。
- 一つの購入候補から複数Boxへ複製する機能。
- Boxから買い物リストへ追加する機能。
- 購入候補の写真、使用色、制作ステータス。
- 購入候補の詳細・編集画面。
