# 混色シミュレーター・色情報UX刷新 設計

## 目的

塗料の在庫・欲しい物を扱う「塗料管理」と、複数色を混ぜた見え方を試す「混色シミュレーター」を明確に分離する。シミュレーターは保存を必須にせず、その場で結果を確認でき、残したい配合だけを独立した「保存済み配合」として登録・編集・削除できるようにする。

同時に、キット詳細の「使用する色」を同じ編集UIへ載せ替え、現在できない構成塗料・配合・名前・メモの編集を可能にする。一覧は省スペースな要約、タップ後は全情報を確認できる詳細表示とし、2色以上でも元の色を識別しやすくする。

## 用語と境界

- **塗料**: `catalog_paints` の製品色。保管箱・お気に入り・買い物リストで購入状況を管理する。
- **保存済み配合**: 混色シミュレーターで任意に保存した配合。キットや在庫には属さない。
- **キット使用色**: 特定キットで使う色。保存済み配合とは別データであり、相互に自動作成・同期しない。
- 保存済み配合とキット使用色はいずれも `catalog_paints.id` を参照し、ブランド・シリーズ・品番・色名・HEXは表示時に現在のカタログ値を読む。過去の表示値はスナップショット保存しない。
- シミュレーターで色を選んでも、保管箱・お気に入り・買い物リスト・キットには書き込まない。

## ナビゲーション

- ドロワーの「塗料一覧」の直下、「設定」の直前に「混色シミュレーター」を追加する。
- Colorack/Kitrackどちらのモードからも同じ独立画面へ移動できる。
- `app/(tabs)/mixing.tsx` を非表示タブとして登録し、画面タイトルも「混色シミュレーター」とする。

## 画面構成

### 混色シミュレーター

画面上部に `[シミュレーター] [保存済み]` のセグメントを常設する。初期表示は「シミュレーター」。選択中セグメントは色だけに頼らず、下線・文字ウェイト・アクセシビリティの selected state でも示す。

「シミュレーター」では、保存前から以下を常時表示する。

- 大きな混色結果スウォッチとHEX。結果がまだない場合は説明付きの空状態。
- 選択済みの構成塗料一覧。アコーディオンには入れない。
- 各行に元色スウォッチ、ブランド、シリーズ、品番、色名、配合率（%）入力、±5%操作、削除操作。
- 塗料種別の選択と、既存の `HierarchyBrowser` / `ColorMatcher` を使う全画面モーダルの塗料選択。選択後はエディタへ戻り、結果色をすぐ確認できるようにする。
- 「保存」「配合をクリア」。保存は名前・メモを入力して保存済み配合を作るが、試すだけなら保存不要。

キット追加時と保存済み配合の編集時は同じエディタをフルスクリーンモーダルで使う。エディタは永続化を行わず、`initialDraft` と `onSave(draft)` を受け取る。呼び出し側が保存済み配合またはキット使用色のDB操作を担当する。

### 保存済み一覧の省略カード

カードはテーマの `surface` / `surfaceAlt` を背景にし、混色結果の上へ文字を直接重ねない。高さは約100pxを目安とし、次の情報に絞る。

- 左: 大きな結果色スウォッチ。
- 右上: 配合名。空の場合は先頭塗料名を代替表示。
- 右: 元色の要約。2色なら両方の「ブランド・品番・色名・割合」を表示する。3〜5色なら先頭2色を表示し「ほかN色」で省略する。
- 下端: 全構成色を比率に応じた幅で並べる細い配合ストリップ。2色を超えても元色の数とおおよその構成を一目で把握できる。
- カード全体を1つのボタンとして扱い、アクセシビリティラベルには配合名・構成色数・結果HEXを含める。

### 詳細表示

カードをタップすると詳細モーダルを開く。

- 大きな結果色、配合名、メモ、結果HEX。
- 全構成塗料を省略せず、元色スウォッチ、ブランド、シリーズ、品番、色名、配合率（%）で表示。
- 「編集」「削除」。削除は確認ダイアログを挟む。
- 保存済み配合とキット使用色で同じ詳細コンポーネントを使う。所有数はキット詳細側だけ補助表示できるが、配合の意味や表示順は共通にする。

### キット詳細の色情報

- 現在の色背景カードとツールチップ中心の `KitColorRow` を、上記の省略カードへ置き換える。
- タップで共通詳細を開き、キット編集モード中は詳細から構成塗料・配合・名前・メモを編集できる。
- 並び替えは縦一覧に合わせて「上へ／下へ」とする。左右矢印は使わない。
- 追加は共通エディタの空draft、編集は現在値を `initialDraft` として開く。

## 配合ルール

- 構成塗料は1〜5色。同じ塗料を重複追加しない。
- 物理的に不適切な種別混在を避けるため、同一配合内は同じ `paint_type` に限定する。最初の選択後は種別を固定し、種別変更には配合クリアが必要。
- 新規選択対象は有効な6桁HEXを持つ塗料のみ。既存データでHEXが欠けた場合は詳細を表示しつつ、結果色を「計算できません」とし、保存時に修正を求める。
- 入力値は1〜100の整数%。合計がちょうど100%の場合だけ保存できる。100%未満は残量、100%超過は超過量を表示する。
- 保存時は%を0〜1のratioへ変換する。保存済みratioの復元では端数を配分し、整数%の合計を必ず100にする。
- 色の追加・削除時は、構成中の全色を整数%で均等配分し、合計100%を維持する。
- エディタには配合全体の色分けバー、合計%、保存可否を表示する。各色は直接入力と±5%ボタンの両方で調整できる。
- 混色結果は既存の `mixHexColors` / `spectral.js` で都度計算し、結果HEX自体はDBへ保存しない。

## データモデル

保存済み配合はキットテーブルから独立させる。

```sql
CREATE TABLE IF NOT EXISTS mix_recipes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT,
  note TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  added_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS mix_recipe_paints (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  mix_recipe_id INTEGER NOT NULL,
  paint_id INTEGER NOT NULL,
  ratio REAL NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0
);
```

`lib/db/mixRecipes.ts` は一覧取得、追加、全項目更新、削除をトランザクションで提供する。更新時は親行を更新し、子行を全削除して現在の1〜5件を順番どおり再挿入する。件数が小さく、差分同期より短く安全なためである。

`lib/db/kitColors.ts` に同じ形の `updateKitColor(id, name, note, paints)` を追加し、名前だけを更新する既存APIは置き換える。取得クエリには `series`、`series_en`、`paint_type` を含める。

## カタログ更新・削除時の参照保護

- 公式カタログ更新・再シード時、`mix_recipe_paints` または `kit_color_paints` から参照中の公式塗料は削除しない。
- 手動塗料を個別削除する前に両方の参照を確認する。参照中なら削除せず、「保存済み配合またはキット使用色から外してから削除してください」と表示する。
- 「塗料一覧を初期化」も参照中の手動塗料がある場合は処理を開始せず、同じ理由を表示する。配合やキット色情報を暗黙削除しない。
- クラウド復元は、配合・キット色の子→親を消してから手動塗料を入れ替え、復元後にcatalog codeから新しいpaint idを解決する。

## クラウドバックアップ

- `BACKUP_SCHEMA_VERSION` を4へ上げ、`mixRecipes?` と `mixRecipePaints?` を追加する。
- recipeのローカルidは `mixrecipe_<id>` 参照へ変換し、塗料は既存と同じ `catalog_code` で保存する。
- v1〜v3バックアップは空の保存済み配合として復元できる。
- v4復元時、親配合またはcatalog codeを解決できない子行は警告してスキップし、孤児行を作らない。
- `isLocalDbEmpty()` は保存済み配合もユーザーデータとして数える。

## 状態・エラー・アクセシビリティ

- エディタを閉じる、Android戻る、スワイプで閉じる際、未保存変更があれば破棄確認を出す。ピッカー階層から戻るだけではdraftを失わない。
- 保存中は多重送信を無効化する。DBエラー時はエディタを閉じず、エラーを表示してdraftを保持する。
- 一覧には読み込み中、空、失敗、再試行の状態を用意する。
- タップ要素は44px以上。アイコン操作にはrole、label、disabled/selected stateを設定する。色だけで情報を表さず、元色名・品番・配合率を併記する。
- ライト／ダーク両テーマで文字コントラストを確保する。配合ストリップは情報補助であり、文字情報の代替にはしない。

## 実装境界

### 再利用するもの

- `lib/colorMix.ts` と既存依存 `spectral.js`
- `components/AddPaint/HierarchyBrowser.tsx`
- `components/AddPaint/ColorMatcher.tsx`
- 既存のテーマ、翻訳、モーダル、スワイプ、空状態コンポーネント
- `kit_colors` / `kit_color_paints` の既存データ

### 新規依存を追加しないもの

- 並び替え用ライブラリ、フォームライブラリ、状態管理ライブラリ、UIキットは追加しない。
- 配合は最大5件のため、子行全置換とReactローカルstateで十分とする。

### 今回やらないもの

- 保存済み配合とキット使用色の同期・リンク・コピー機能。
- 在庫量、価格、購入予定との連携。
- 実塗料の顔料、隠蔽力、希釈剤、乾燥後変化を考慮した物理シミュレーション。
- 配合の画像共有、タグ、フォルダ、検索、複製、履歴、クラウド共同編集。
- アプリ全体の配色や主要ボタン色の一括変更。主要ボタンのコントラスト見直しは別改善候補として記録する。

## 検証

- TDDで、整数%とratioの変換、合計100%検証、重複・上限・種別・HEX検証、追加／削除時の均等再配分を先に失敗させる。
- DB保存層で、一覧の表示情報、追加、全項目編集、削除、子行順序を検証する。
- バックアップでv4生成、v1〜v3互換、v4復元、欠損参照スキップ、ローカル空判定を検証する。
- 手動塗料削除／初期化が参照中データを破壊しないことを検証する。
- `npm run test` と `npm run typecheck` を実行する。
- Webまたは実機で、セグメント切替、1〜5色のライブ結果、2色カード、3〜5色省略、詳細、追加、編集、削除、dirty破棄確認、ライト／ダーク、英語／日本語、Android戻るを確認する。

## 今回外の改善提案

- アプリ全体のprimary背景に白文字を載せる箇所は、ライト／ダーク双方でコントラストを再測定し、テーマトークン単位で改善する価値がある。
- 長い一覧の編集モードは操作密度が高くなりやすいため、今後は「閲覧カード→詳細で編集」のパターンを在庫・キット・塗料詳細にも横展開できる。ただし今回の変更対象には含めない。
