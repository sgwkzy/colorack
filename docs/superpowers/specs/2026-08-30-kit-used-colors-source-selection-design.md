# Kitrack 使用色の追加元選択 設計

## 目的

Kitrack のキット詳細で、ユーザーが次の3つの追加元から迷わず使用色を登録できるようにする。

1. 塗料一覧にある既存塗料
2. 混色シミュレーターの保存済み混色
3. キット詳細内で新しく作る混色

キットで使う色と、混色シミュレーターで再利用する保存済み混色は用途が異なる。両者を同期対象にせず、追加時に内容をコピーした後は完全に独立したデータとして扱う。

## 用語

- **キット使用色**: 特定のキットでどこに何色を使うかを記録する `kit_colors` / `kit_color_paints` のデータ。
- **保存済み混色**: 混色シミュレーターで再利用する `mix_recipes` / `mix_recipe_paints` のデータ。
- **コピー**: 名前・メモ・構成塗料・配合率を別の独立レコードとして保存すること。コピー元との関連付けや同期は行わない。

## 採用方針

### 完全独立

- キット使用色と保存済み混色を結ぶIDや同期状態は追加しない。
- 片方を編集または削除しても、もう片方は変更しない。
- 編集時に「両方を更新」「新しい色として追加」などの分岐を表示しない。
- 同じ配合を複数回登録できる。キット内の使用箇所やメモが異なる可能性があるため、重複を禁止しない。
- 初回実装では「保存済み混色にも追加」チェックボックスを設けない。Kitrack で新しく作った混色はキット使用色だけに保存する。

この方針により、ユーザーは現在開いているデータだけを編集すればよく、意図しない上書きや同期状態の判断が発生しない。

## 画面構成

### キット詳細

- タブ名を「色情報」から「使用色」に変更する。
- セクション見出しを「このキットで使う色」にする。
- 追加操作は「＋ 使用色を追加」に統一する。
- 既存の使用色カード、詳細表示、編集、削除、並び替えは維持する。
- タブと追加操作には `accessibilityRole`、選択状態、具体的な読み上げラベルを設定する。

### 追加元選択モーダル

「＋ 使用色を追加」を押すと、次の3項目を縦に並べたモーダルを表示する。

1. **塗料から選ぶ**  
   塗料一覧から1色を追加
2. **保存済み混色から選ぶ**  
   シミュレーターで保存した配合をコピー
3. **新しく混色を作る**  
   このキット専用の配合を作成

各項目は最低48ptのタップ領域を持ち、タイトルと説明を一つの読み上げ単位にする。説明によって、タップ後の結果を選択前に理解できるようにする。

戻る操作は子画面だけを閉じ、キット詳細へ戻る。追加元選択からキット詳細そのものを閉じない。

## 追加フロー

### 1. 塗料から選ぶ

1. 既存の塗料一覧／近似色検索を選択専用モードで開く。
2. 塗料を1件選択する。
3. `kit_colors` に塗料名を初期名として登録する。
4. `kit_color_paints` に選択した塗料を配合率 `1.0`、先頭順序で登録する。
5. モーダルを閉じて使用色一覧を更新する。

塗料種別を事前に選ばせず、一覧側の既存フィルターや階層から目的の塗料を探せるようにする。保存後の名称・メモは通常のキット使用色編集で変更できる。

### 2. 保存済み混色から選ぶ

1. 保存済み混色を既存の省略カードで一覧表示する。
2. 画面見出しと読み上げラベルで「キットに追加する混色を選択」と明示する。
3. カードを選択すると、元の名前・メモ・構成塗料・配合率・塗料順をキット使用色へコピーする。
4. コピー完了後に一覧を閉じ、キット使用色一覧を更新する。

配合率は表示用に丸めた整数パーセントを経由せず、保存済みの `ratio` をそのままコピーする。保存済み混色が0件の場合は、空状態と「混色シミュレーターで保存するとここから選べます」という案内を表示する。

### 3. 新しく混色を作る

1. 既存の `ColorMixEditorModal` を空の状態で開く。
2. ユーザーが構成塗料、合計100%の配合率、任意の名前・メモを入力する。
3. 保存ボタンは「キットに登録」と表示する。
4. `kit_colors` / `kit_color_paints` にだけ保存する。
5. 保存済み混色は作成しない。

既存の1〜5色、同一塗料種別、HEX値、整数パーセント、合計100%の検証をそのまま使用する。

## 編集と削除

- キット使用色の編集は、選択した `kit_colors` と子レコードだけを更新する。
- 保存済み混色の編集は、選択した `mix_recipes` と子レコードだけを更新する。
- どちらの編集画面にも相手側を更新する選択肢を表示しない。
- 保存済み混色からコピーしたキット使用色も、通常のキット使用色として編集・削除する。
- コピー元の保存済み混色を削除しても、キット使用色は残る。
- キット使用色を削除しても、コピー元の保存済み混色は残る。

「キット使用色を保存済み混色として複製」などの逆方向操作は、実際の利用要望が確認できるまで追加しない。

## データとトランザクション

- DBスキーマを変更しない。
- バックアップ形式を変更しない。
- 既存の `addKitColor` が持つトランザクションを利用し、親レコードと構成塗料を一括保存する。
- 保存済み混色からのコピーでも、新しいキット使用色として `addKitColor` を呼ぶ。
- コピー元IDを保存しない。
- 追加処理中は再操作を無効化し、二重登録を防ぐ。
- 失敗時は追加元画面を維持し、再試行できるエラーを表示する。中途半端な親レコードや子レコードを残さない。

## コンポーネント方針

既存コンポーネントを優先して再利用し、追加する責務を限定する。

- `KitDetailModal`: タブ名、追加CTA、追加元選択の状態管理。
- `KitColorComposerModal`: 3経路を管理する入口へ変更。
- `ColorMixPaintPickerModal`: 塗料種別を固定しない選択モードにも対応。
- `ColorMixCard`: 保存済み混色の選択一覧で再利用。
- `ColorMixEditorModal`: 新規混色作成と既存使用色編集で再利用。
- `addKitColor` / `getMixRecipes`: 既存DB関数を再利用。

同期サービス、リンクテーブル、共有配合モデル、新しい状態管理ライブラリは追加しない。

## ローディング・空状態・エラー

- 保存済み混色一覧の読み込み中はローディング表示を出す。
- 保存済み混色がない場合は説明付き空状態を出す。
- 読み込み失敗時はエラーメッセージと再試行操作を出す。
- 保存中は対象操作を無効化し、二重タップを防ぐ。
- 保存失敗時は入力や選択を保持し、再試行できる。
- 成功時はモーダルを閉じて一覧の更新結果を表示し、追加成功だけを伝えるトーストは必須としない。

## アクセシビリティ

- タブには `accessibilityRole="tab"` と選択状態を付ける。
- 追加CTAと3つの追加元には `accessibilityRole="button"` を付ける。
- 保存済み混色カードは「名称、構成色数、キットに追加」の順に読み上げる。
- 読み込みエラーはアラートとして通知する。
- 無効な保存操作には無効状態を付ける。
- すべての主要操作で最低48ptのタップ領域を維持する。

## テスト

### ロジック／DB

- 既存塗料が1色・配合率100%のキット使用色として保存される。
- 保存済み混色の名前・メモ・塗料順・元のratioが正確にコピーされる。
- コピー後に保存済み混色を編集・削除してもキット使用色が変化しない。
- コピー後にキット使用色を編集・削除しても保存済み混色が変化しない。
- 同じ配合を複数回コピーできる。
- 親または子の保存失敗時に全体がロールバックされる。
- 新規混色はキット使用色だけに保存される。
- 100%でない新規混色は保存できない。

### UI

- 「使用色」タブから追加元3択を開ける。
- 各追加元から正しい子画面へ移動できる。
- 子画面の戻る操作がキット詳細へ戻る。
- 保存済み混色のローディング、空状態、失敗、再試行が表示される。
- 保存中の二重操作が防止される。
- 既存のキット使用色の詳細、編集、削除、並び替えが回帰しない。

### 完了確認

- `npm run test`
- `npm run typecheck`
- `git diff --check`
- Expo Go実機で3経路、編集・削除の独立性、戻る操作、長い色名、VoiceOver読み上げを確認する。

## 対象外

- キット使用色と保存済み混色の同期
- 両方を同時更新する編集フロー
- 新規混色の保存済み混色への自動／任意同時登録
- キット使用色から保存済み混色への逆方向コピー
- コピー元表示や履歴
- 配合の重複検出
- DBスキーマまたはバックアップschemaの変更
